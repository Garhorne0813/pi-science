让文件引用回到
真正被讨论的位置。

从“输入区上方的一排附件”升级为“文字中的结构化引用”。可见文字负责语义，实体元数据负责对象身份，原生 textarea 继续负责编辑与输入法。

基于 main@10ff1f6bPhase 1 · textarea + mirror兼容既有消息协议

为什么需要改？

科学工作流往往在一句话中描述多个文件的角色。脱离正文的附件区只能告诉系统“有哪些文件”，无法稳定说明“哪一个是基线、哪一个是变体”。

01 / POSITION

语义位置

把 WT.pdb、mutant.pdb、control.csv 直接放进问题中，而不是依赖“第一个附件”。

02 / IDENTITY

机器可读身份

显示的 @name 不负责解析身份；实体保存工作区、路径与类型。

03 / ATOMICITY

原子编辑

选中后成为不可分割的引用；删除令牌时自动同步移除其绑定。

三种行为，一眼看懂

关键边界：当前 cwd + path 不是永久不变的文件 ID。重命名、移动、覆盖、删除与权限变化必须在后续版本通过显式校验解决，不能把显示名当作可靠身份。


哪些做在当前分支，哪些还要补？
优先级内容交付定义
P0 · 已编码行内补全、原子删除、单一实体数组、发送去重需要 CI、键盘、输入法与视觉测试验证
P0 · 验收长路径/多引用、连续撤销、中文/日文/韩文 IME、粘贴剪切、无障碍不能仅靠单元测试认定完成
P1 · 推荐发送前文件有效性、同名消歧、重命名追踪、稳定身份避免静默引用错误对象
P1/P2 · 拓展结构化剪贴板、dataset/run/artifact、更多类型、真实富文本芯片新需求达到镜像几何上限时再评估编辑器迁移
