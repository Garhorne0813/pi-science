# Conversation-native Auto Research (issue #150)

Auto Research runs in the current conversation Agent through `skills/auto-research`. Start from a blank conversation's Research/Optimize/Compare/Evaluate/Reproduce button, invoke `/skill:auto-research <objective>`, or ask for research in ordinary language. The buttons send a normal prompt; they neither create a second task nor call a Research API. Objectives, protocols and material missing assumptions are confirmed through the existing questionnaire/reply UI. Stop uses the Conversation abort button. Continue in the same conversation by asking to resume the saved checkpoint.

## Method and tools

Every task first writes a versioned Evaluation Protocol. Quantitative work creates and validates its own evaluator and comparable baseline; literature/exploratory work uses coverage, citation integrity, independent evidence and explicit gaps. There is no built-in universal evaluator or score. Researcher and Reviewer definitions are in the skill's `agents/` directory. The parent dynamically selects bounded subquestions; the existing `subagent.tasks` supports up to four parallel same-role instances. Reviewer returns structured checks and blockers independently of objective measurements.

Agent discovery and runtime resolution share `agent-definitions.ts`. Namespaced roles use `skill/agent`; bare project definitions and builtin roles remain available, including legacy filename aliases. Effective skill precedence follows the catalog (project, user, builtin). Current parent resource policy is checked at dispatch, including live disabling. Child tools are intersected with the parent's allowance; MCP and questionnaire tools remain unavailable to children. The parent retrieves sources and performs experiments. Installation/import/update retains role/reference directories, and uninstall removes the full project skill tree. Existing managed builtin seeding copies these directories too.

## Checkpoints, provenance and limits

`research/<id>/` holds plan, protocol, optional evaluator/baseline, state, evidence, experiment parameters/results, protocol revision snapshots and report. Checkpoints list completed IDs, input/evaluator versions, remaining budgets and session/run/artifact references. They are semantic files, not a new scheduler. Existing Session, Runs, Artifacts and Provenance retain execution authority. Files and report links open through the existing inspector; tool and child activity appears in the Conversation transcript.

`execution_budget` is a generic Harness tool. It durably reserves expensive tool calls against the operation ID, serializes concurrent admission, reuses admitted invocation memos on replay, and aborts tool signals at deadlines. A reservation failure between disk commit and memo is conservative and may consume an extra slot. The agent sets agreed remaining time/call limits before research retrieval/delegation/computation. Limits can shrink but cannot expand during an operation. Generic defaults/ceilings are 3,600 seconds and 100 calls per operation; each execution has a 600-second ceiling. Bash, subagent, notebook and MCP tools use the wrapper; underlying kernel/job/connector limits still apply. Notebook execution propagates the remaining timeout to the kernel; gateway response grace does not expand the actual cell execution limit. Read/write/edit, questionnaires and final reporting remain available to checkpoint/explain exhaustion.

These hard limits count tool invocations, not model tokens, dollars, arbitrary internal script iterations or semantic experiments. A parallel/chain subagent invocation counts once and remains separately bounded by the existing dispatcher. Experiment counts are tracked in the protocol/checkpoint; use one bounded experiment per execution and a conservative execution-call limit. Model-token/cost stopping limits from the old dedicated loop are not transferred to a new scheduler. Continuation is a new conversation operation, so the skill explicitly restores remaining allowances from the checkpoint. Hard time/call admission persists across Worker recovery within the same operation.

The skill does not promise unattended/background recovery after browser closure. Generic AgentHarness operation recovery continues to work; a stopped/interrupted research task can be resumed by the user with saved context. Do not automatically repeat completed experiments or silently replenish a research budget.

## Dependency audit and history compatibility

Removed: `apps/server/src/research-loop/` (Coordinator, supervisor runner, intent compiler, reducer, event channel, writer/repository and stop policy), dedicated Research contracts and API registrations, server startup research reconciliation/shutdown, `ResearchPage`, its explicit route/navigation entry, loop controls/hook, Research clients and SSE subscriptions. The generic SubagentBridge/Dispatcher, AgentHarness, project review, JobCoordinator, scientific kernels/notebooks, execution/artifact/provenance routes and session storage remain.

Audit found the old loop was referenced by server module wiring, project routes, workspace rename/delete guards, Conversation setup controls, Knowledge summaries and smoke tests. Those callers now use the conversation skill or read-only legacy memory. Workspace destructive-operation guards still enforce active generic jobs; no retired research scheduler can start new jobs. The shared execution-surface discriminator still accepts `research-loop` so old execution/job records render correctly. Hidden session ownership data is retained and old transcripts stay on disk.

The original `research-records-v2.jsonl` remains intact under `metadataRoot`, including relocated project storage. `/api/project-memory/timeline` exposes historical records; `/api/project-memory/archives` lists metadata without copying artifacts or creating files. Explicit preview/continuation uses `POST /api/project-memory/archives/:id/export` to export content-addressed JSON under `research/archives/<id-hash>/`, preserving evaluator records and original execution references. Referenced solution/run files (including outputs and evaluator results) are copied without executing them, bounded to 1,000 visited entries, 64 MiB and 10 seconds per export; `export_truncated` records incomplete exports and original references remain available; foreign symlinks are excluded and export destinations must remain inside the workspace. Original records/artifacts are neither deleted nor status-rewritten, including tasks last stored as running. Missing original files remain referenced in the archive and are not fabricated. No legacy scheduler restarts them.

`/workspace/:cwd/research` and older nested Research bookmarks are handled by the generic workspace compatibility redirect to `/knowledge?tab=research`. Knowledge offers archive preview and **Continue in Conversation**, which opens an explicit blank conversation draft with the archive path. The new Agent inspects old evidence/results, establishes a new protocol and carries forward valid results. The legacy Research POST/GET/event/evaluator endpoints return 404; this compatibility path is read-only and never calls those endpoints.
