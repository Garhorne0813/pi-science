# Conversation-native Auto Research

Auto Research runs in the current conversation Agent through `skills/auto-research`. Start from a blank conversation's Research/Optimize/Compare/Evaluate/Reproduce button, invoke `/skill:auto-research <objective>`, or ask for research in ordinary language. The buttons send a normal prompt; they neither create a second task nor call a Research API. Objectives, protocols and material missing assumptions are confirmed through the existing questionnaire/reply UI. Stop uses the Conversation abort button. Continue in the same conversation by asking to resume the saved checkpoint.

## Method and tools

Every task first writes a versioned Evaluation Protocol. Quantitative work creates and validates its own evaluator and comparable baseline; literature/exploratory work uses coverage, citation integrity, independent evidence and explicit gaps. There is no built-in universal evaluator or score. Experimenter, Researcher and Reviewer definitions are in the skill's `agents/` directory. Experimental optimization is the primary workflow; deep literature research and mixed workflows remain supported without requiring a numerical benchmark or every role. The parent dynamically selects bounded subquestions; the existing `subagent.tasks` supports up to four parallel same-role instances. Reviewer returns structured checks and blockers independently of objective measurements.

Agent discovery and runtime resolution share `agent-definitions.ts`. Namespaced roles use `skill/agent`; bare project definitions and builtin roles remain available, including legacy filename aliases. Effective skill precedence follows the catalog (project, user, builtin). Current parent resource policy is checked at dispatch, including live disabling. Child tools are intersected with the parent's actual active tool set and exact role declarations; questionnaire tools remain unavailable. Before each child tool call, authenticated IPC checks the parent's live skill policy, role definition and active capabilities again. MCP tools also reload current projected project/global policy before dispatch. Disabled/denied tools and changed connector identities fail closed. Prefix/wildcard role declarations do not grant MCP capabilities. Researcher declares the four existing Web Access tools and the five Paper Search tools; project overrides may add other exact scientific MCP IDs. Hidden children require tool preauthorization in existing MCP settings; an ask-only call fails immediately with a permission dependency, without silently granting approval or waiting for hidden UI. A parent's one-off approval does not authorize arbitrary child calls. The parent may instead retrieve through its normal approval UI and supply evidence. No new Web Access server or fetch alias is added. Installation/import/update retains role/reference directories, and uninstall removes the full project skill tree. Existing managed builtin seeding copies these directories too.

## Checkpoints, provenance and limits

`research/<id>/` holds plan, protocol, optional evaluator/baseline, state, evidence, experiment parameters/results, protocol revision snapshots and report. Checkpoints list completed IDs, input/evaluator versions, remaining budgets and session/run/artifact references. They are semantic files, not a new scheduler. Existing Session, Runs, Artifacts and Provenance retain execution authority. Files and report links open through the existing inspector; tool and child activity appears in the Conversation transcript.

`execution_budget` is a generic Harness tool. It durably reserves expensive tool calls against the owning operation ID (including hidden child calls), serializes concurrent admission, reuses admitted invocation memos on replay, and aborts tool signals at deadlines. A reservation failure between disk commit and memo is conservative and may consume an extra slot. The agent sets agreed remaining time/call limits before research retrieval/delegation/computation. Limits can shrink but cannot expand during an operation. Generic defaults/ceilings are 3,600 seconds and 100 calls per operation; each execution has a 600-second ceiling. Bash, subagent, notebook and MCP tools use the wrapper; underlying kernel/job/connector limits still apply. Notebook execution propagates the remaining timeout to the kernel; gateway response grace does not expand the actual cell execution limit. Read/write/edit, questionnaires and final reporting remain available to checkpoint/explain exhaustion.

These hard limits count tool invocations, not model tokens, dollars, arbitrary internal script iterations or semantic experiments. A parallel/chain subagent dispatch counts once; each costly child call additionally reserves from the same shared allowance, rather than receiving a fresh 100-call cap. Children cannot change the budget scope; limits may only narrow. Experiment counts are tracked in the protocol/checkpoint; use one bounded experiment per execution and a conservative execution-call limit. Model-token/cost stopping limits from the old dedicated loop are not transferred to a new scheduler. For durable research across operations, call `execution_budget` with `research_id`, `max_seconds` and `max_executions` before the first expensive call or operation-budget setup. Resume by binding the new operation to the same `research_id`. Binding cannot change during an operation; an existing research scope never expands its deadline or call limit. Limits are committed before the binding, admission is atomic across workers, and failed/cancelled admitted calls remain consumed. The deadline is wall-clock time, including pauses. A missing inherited budget or corrupt saved budget/scope fails closed. Ordinary tasks without research_id retain operation-scoped budgets. Research scopes are selected explicitly by the Agent; changing IDs across operations is not automatic recognition of the same study.

The skill does not promise unattended/background recovery after browser closure. Generic AgentHarness operation recovery continues to work; a stopped/interrupted research task can be resumed by the user with saved context. Do not automatically repeat completed experiments or silently replenish a research budget.

## Dependency audit and history compatibility

Removed: `apps/server/src/research-loop/` (Coordinator, supervisor runner, intent compiler, reducer, event channel, writer/repository and stop policy), dedicated Research contracts and API registrations, server startup research reconciliation/shutdown, `ResearchPage`, its explicit route/navigation entry, loop controls/hook, Research clients and SSE subscriptions. The generic SubagentBridge/Dispatcher, AgentHarness, project review, JobCoordinator, scientific kernels/notebooks, execution/artifact/provenance routes and session storage remain.

Audit found the old loop was referenced by server module wiring, project routes, workspace rename/delete guards, Conversation setup controls, Knowledge summaries and smoke tests. Those callers now use the conversation skill or read-only legacy memory. Workspace destructive-operation guards still enforce active generic jobs; no retired research scheduler can start new jobs. The shared execution-surface discriminator still accepts `research-loop` so old execution/job records render correctly. Hidden session ownership data is retained and old transcripts stay on disk.

The original `research-records-v2.jsonl` remains intact under `metadataRoot`, including relocated project storage. `/api/project-memory/timeline` exposes historical records; `/api/project-memory/archives` lists metadata without copying artifacts or creating files. Explicit preview/continuation uses `POST /api/project-memory/archives/:id/export` to export content-addressed JSON under `research/archives/<id-hash>/`, preserving evaluator records and original execution references. Referenced solution/run files (including outputs and evaluator results) are copied without executing them, bounded to 1,000 visited entries, 64 MiB and 10 seconds per export; `export_truncated` records incomplete exports and original references remain available; foreign symlinks are excluded and export destinations must remain inside the workspace. Original records/artifacts are neither deleted nor status-rewritten, including tasks last stored as running. Missing original files remain referenced in the archive and are not fabricated. No legacy scheduler restarts them.

`/workspace/:cwd/research` and older nested Research bookmarks are handled by the generic workspace compatibility redirect to `/knowledge?tab=research`. Knowledge offers archive preview and **Continue in Conversation**, which opens an explicit blank conversation draft with the archive path. The new Agent inspects old evidence/results, establishes a new protocol and carries forward valid results. The legacy Research POST/GET/event/evaluator endpoints return 404; this compatibility path is read-only and never calls those endpoints.

## V5 incremental implementation and remaining acceptance

Current execution mode is **candidate code generation with parent-controlled execution**. `auto-research/experimenter` is discoverable but has only `read`; it returns structured proposed files, parameters, repairs and limitations. Runtime also clamps this role to read-only even when a project definition declares broader tools. The parent checks proposed code before saving it in separate candidate directories and running existing controlled tools. These tools do not yet provide candidate mount/process isolation. Do not run untrusted candidate code that requires that protection, enable write/bash/notebook on Experimenter, or claim fully autonomous sandbox execution. `experiment-safety.md` lists the filesystem, symlink, process, resource, network and credential controls required before lifting this fallback.

The protocol freezes evaluation.yaml, original data, baseline and a validated task-specific evaluator. Official rankings require independent reevaluation; candidate metrics are debugging observations. Reviewer can block improved scores for final-test leakage, inconsistent evaluator versions or missing protection. These are workflow contracts in this increment, not new OS-enforced read-only evaluator mounts. Candidate result/checkpoint contracts carry experiment IDs, code/data/evaluator versions, actual runs/artifacts, failures and observed resource usage. There is no exact script-internal experiment, CPU/GPU, token or dollar meter; the implemented shared budget counts admitted expensive calls and wall time.

Researcher treats webpages/papers/README content as untrusted evidence. Save URL/DOI, timestamps, excerpts/content hashes and real artifact references; Web Access responseId remains worker-local temporary state, never a cross-worker or restart recovery key. Existing Conversation, session, run, artifact, provenance and checkpoint infrastructure is reused. No Research page/API/coordinator, literature HTTP gateway or retrieval database is restored.

Authorization uses the proposal's explicit preauthorization transition path. Delegated interactive approval routing is not implemented: ask-only child calls return an actionable error, while normal parent calls retain the existing approval UI. Explicit deny overrides preauthorization. Changing transport/connector identity requires worker refresh; current policy is checked again on every MCP call. Revoking a skill blocks subsequent child calls, but does not retroactively undo a completed or in-flight call.

Validation must distinguish local transport fixtures from scientific acceptance. Local SDK/Worker fixtures cover authorized retrieval, refused ask, dynamic deny/disable/revocation, live skill disabling, read-only Experimenter capability discovery, shared admission, concurrent exhaustion and continuation. Full public Search → Fetch → Pagination, actual-model experimental/deep/mixed tasks, scientific metric quality and adversarial OS sandbox acceptance remain deployment work; this increment does not mark those V5 Definition-of-Done items complete.

Server tests used isolated PI_SCIENCE_HOME under ignored .cache/. `pnpm typecheck`, `pnpm build` and `git diff --check` passed; the existing Vite large-chunk advisory remains. The child retrieval test uses an actual local MCP SDK server and child Worker with a controlled model fixture, not public search or a real scientific reasoning evaluation.
