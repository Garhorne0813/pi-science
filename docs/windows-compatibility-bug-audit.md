# Windows compatibility and bug audit

## Scope and method

This pass inspected the Node control plane, React/UAT tooling, Python runtime, package scripts, and CI for path containment, home/PATH handling, executable discovery, process trees, virtual environments, symlinks, and POSIX-only assumptions. Fixes are limited to reproducible or source-provable defects that do not require a product or architecture change.

## Findings fixed

| Area | Defect | Fix / regression evidence |
|---|---|---|
| Workspace security | Node rejected valid managed children/files whose names begin with `..` (for example `..results`) because containment used a raw `startsWith("..")` check. | Shared `pathIsInside` boundary check; Node/Python parity tests cover `..results`. |
| Workspace security | A missing target below a symlinked directory could pass Node's lexical check and later write outside the workspace. | Missing paths now canonicalize the nearest existing ancestors; regression test rejects `escape/future.txt`. |
| Workspace security | A symlink configured as `PI_SCIENCE_WORKSPACES` rejected its own unmarked children. | Existing managed roots are canonicalized in Node and Python; mirrored tests now accept the child. |
| Workspace security | Metadata-component rejection was case-sensitive, so `.PI-SCIENCE` could alias the protected `.pi-science` directory on Windows and other case-insensitive filesystems. | Node and Python conservatively case-fold the reserved component on every platform; mirrored parameterized regressions cover Linux, macOS, and Windows verdict parity. |
| Windows home paths | Catalog/config defaults and `~/` expansion used only `HOME`, which is not guaranteed on Windows, one skill validation dispatch recognized `~/` but not `~\\`, and a bare `~` resolved as a literal directory name. | Central `userHome` fallback uses `HOME`, then `USERPROFILE`, then `os.homedir()`; bare `~` and both tilde separator forms use the same expansion path. |
| Windows executables | Tool discovery only tried the bare name and `.exe`, ignored `PATHEXT`, quoted PATH entries, and PATH key casing; it also accepted directories/non-executable POSIX files and could stop before a later valid PATH entry. | Cross-platform executable lookup covers `PATHEXT`, quoted entries, and `PATH`/`Path`/`path`, requires regular files, and enforces POSIX execute permission. |
| Windows environment provisioning | Workspace venv creation, tool probing, job capability metadata, and backend no-venv kernel fallback could default to `python3`, which is commonly absent on Windows. A `Path`-only inherited environment was also dropped while a second `PATH` key was emitted. | Platform-correct Python defaults are used by provisioning/catalog/jobs, backend kernels fall back to `sys.executable`, and Windows environment composition preserves the inherited path under one canonical `PATH` key. |
| Missing Pi runtime | Session creation provisioned a full workspace venv before noticing that `PI_CLI_PATH` was absent, making a deterministic 503 slow enough to time out on Windows. | Fail fast with `spawn_failed` before environment provisioning when no runtime is configured. |
| Windows kernel PATH | Python kernels added `<npm-prefix>/bin`; npm global shims live at `<npm-prefix>` on Windows. | Platform-specific npm executable directory with a unit test. |
| Windows process lifecycle | Cancelling a job killed only the immediate process, leaving descendants alive and pipes open. | Windows uses `taskkill /T /F`; the lifecycle test now uses a cross-platform Node grandchild. |
| Windows Pi runtime launch | Deriving the repository root from `new URL(import.meta.url).pathname` duplicated the drive prefix (`D:\\D:\\...`) and prevented builtin skills from being seeded. Runtime arguments also always added an obsolete `pi-subagents/index.ts` beside the manifest-discovered extension. | Convert the module URL with `fileURLToPath`, remove the legacy duplicate, and regression-test a temporary runtime manifest whose existing extension is passed exactly once. |
| Windows research loops | Candidate execution assumed `bash` was directly on PATH, missed the standard per-user `%LOCALAPPDATA%\\Programs\\Git` install root, and the restricted research-job environment discarded Windows process essentials such as `SystemRoot`, `ComSpec`, `PATHEXT`, and user profile/application-data paths. Environment-key matching also depended on a few exact casing variants. Native CI showed evaluator and process-tree jobs could remain running instead of closing. | Resolver supports `PI_SCIENCE_BASH_PATH`, PATH/PATHEXT, system and per-user Git for Windows locations, with an actionable missing-bash error. The restricted environment matches its allowlist case-insensitively, emits one canonical key per value, and still excludes unrelated mixed-case secrets. Job regressions check preservation, canonicalization, and redaction. |
| Windows UAT | All browser UAT scripts hard-coded the macOS Google Chrome path. | Shared discovery supports Chrome/Chromium/Edge on macOS, Linux, and Windows and validates `CHROME_PATH`. |
| Cross-platform tests/CI | Tests split PATH on `:`, removed live Node/Python child runtimes before shutdown (allowed on POSIX but locked on Windows), and assumed venv-backed job integration completed within 5 seconds. The first Python cleanup fix shut kernels down in the client fixture but did not order that teardown ahead of the independent temporary-workspace fixture. CI never ran on Windows. | Use `path.delimiter`, make the client fixture depend on the temporary workspace so kernel shutdown is guaranteed before workspace cleanup, give provisioning integration tests platform-realistic bounds, and run the quality suite on Ubuntu and Windows. POSIX smoke remains Ubuntu-only. |
| Research lifecycle | Completing or cancelling a loop between job submission and durable job publication could leave an execution/evaluator job running and reopen a finalized operation. Process-tree tests could also cancel as soon as the parent was recorded running, before proving the descendant existed. | Post-submit publication re-checks loop, candidate, and operation eligibility under the repository lock; late jobs are cancelled and deterministic hooked tests cover both execution and evaluation windows. Lifecycle regressions wait for a file readiness marker written by the descendant before completing or cancelling the loop/job. |
| Workspace deletion | Deletion initially used separator-sensitive string prefix logic; the first boundary fix remained lexical and did not reject an intermediate symlink or Windows junction beneath the managed root. | The endpoint now combines lexical and canonical containment, walks every existing path component with `lstat`, rejects symlink/junction traversal, and recursively removes the canonical checked target. HTTP regressions cover the managed root, prefix-sharing siblings, valid children, and `managed/escape -> outside` without touching the outside sentinel. |

## Deferred risks and non-goals

- Installation/start/stop/smoke scripts are Bash programs. A native PowerShell installer and service supervisor would be a separate user-facing delivery project, not a safe bug-fix-only change.
- Research candidate contracts still intentionally produce `solve.sh`; Windows therefore requires Git for Windows/MSYS bash or `PI_SCIENCE_BASH_PATH`. Supporting PowerShell/Python entrypoint contracts requires an approved cross-platform research execution design.
- POSIX process groups provide graceful-then-force semantics; Windows `taskkill /T /F` is necessarily forceful.
- This environment is macOS, so real Windows execution is delegated to the new `windows-latest` CI leg. Platform-specific unit tests exercise Windows path/executable decisions locally but do not replace a native run.
- Workspace deletion performs validation immediately before recursive removal, but filesystem containment checks cannot eliminate a privileged local actor's check-to-use race entirely. The route removes the canonical path it checked and rejects all symlink/junction components observed during validation; OS-level directory handles or sandboxing would be a separate architecture change.
- Shell-based smoke/UAT services, SSH tooling availability, Windows symlink privileges, and long-path policy remain host-policy areas not covered by the bug-fix scope.
