# PR #115：agent-core 运行时优化方案

> 更新：当前已移除 Orbit 运行时，统一使用 Agent Core；以下阶段性记录中的 opt-in/兼容计划属于历史状态。现行会话处理见[转换说明](agent-core-session-conversion.md)。

日期：2026-10-01。状态：主要代码改造已完成，保持内部 opt-in；发布验收与扩展边界见 [实施记录](agent-core-runtime-implementation.md) 和 [能力清单](agent-core-capability-inventory.md)。

基线：PR #115，提交 `6110b446da7cbff2a41e94ff12173cb8aacfff01`。当前 `pi-agent-core`、`pi-ai` 均锁定 `0.87.1`；本次检查 npm 时，两者最新版本均为 `0.99.2`。

本方案依据最近两次关于运行时 PRD、上下文压缩与 subagent/todo 能力来源的分析，更新原文档基于 `7efa2048` 的判断。OS 级 sandbox 按已有约定暂缓；继续保留 `PI_SCIENCE_AGENT_RUNTIME=agent-core` 开关和 Orbit 路径。

后续通信层精简与前端协议收敛见 [Agent-core 通信与前端协议收敛方案](prd-agent-core-communication-optimization.md)。该方案尚未实施，不代表 Orbit 已满足退役条件。

## 1. 目标与范围

让 agent-core 会话具备现有研究对话所需的产品能力：配置与运行事实一致，压缩可观测，turn 产物和复查正常，todo 与子代理可恢复，迁移不丢数据。

架构继续使用 `AgentHarness`。Pi-Science 的 Settings、凭据、受管 MCP、研究循环、项目复查、Notebook 和浏览器界面继续承担各自的产品职责。

本轮规划不包含嵌入 coding-agent SDK、codemode、虚拟模型、订阅登录或新的权限 UI。图片发送单独列为后续端到端能力。切换默认运行时和删除 Orbit 使用独立验收门槛。

- 按会话串行配置、部分失败回滚和 harness 日志作为已应用模型配置的来源。
- 持久化归属、迁移来源及删除标记，避免旧 transcript 复活。

- 按需重开 Worker、durable operation 恢复及空闲回收。

## 3. 阶段一：独立升级上游基线

将 `pi-agent-core`、`pi-ai` 一起锁定到经验证的 `0.99.2`，更新 lockfile。升级单独提交，便于识别行为变化。

重新核对 `AgentHarness.create`、`accept/drive/resume`、watch/snapshot、配置 setter、工具执行、技能加载及 session repo 的接口和行为。现有 admission 与恢复设计继续使用公开 API。

验收包括新建会话，也包括由 `0.87.1` 写出的已有 v4 文件。完整保留丢失确认、重复 prompt、恢复订阅、配置部分失败、迁移删除及凭据投影回归。覆盖 Worker 启动路径的 Linux/Windows 差异。

编译通过不代表行为兼容。升级验收须证明已有会话可读、未完成操作可恢复、同一请求不重复接收；不能只验证一个新会话的普通 prompt。

完成标准：类型检查、服务端构建和相关回归通过；升级提交包含明确的存储兼容结论。发布回退前须验证新版本写出的会话是否仍可被旧版本读取，不能只回退依赖版本。

## 4. 阶段二：统一模型、上下文与压缩事实

### 4.1 模型资源

由 canonical model resources 与受管凭据提供产品模型事实，使用适配层构造 Harness 所需的模型对象。Settings 列表、保存模型、Worker 选择及冷态查询使用同一解析结果。

- 保留可用的内置模型，并纳入已有自定义 provider/model 和 endpoint 配置。
- 复用现有模型路由及可用性规则，不在 worker 中另建一份独立模型配置或密钥库。
- 根据当前模型的 `thinkingLevelMap` 和上游能力语义计算思考档；不简单返回七档，也不直接把映射键集合当作完整能力。
- 对不支持的档位在配置变更前返回明确错误；非推理模型只暴露其实际支持的设置。
- 本阶段只接已有 API key 与受管凭据。只有 OAuth 且尚未适配的 provider 显示现有不可用/需登录状态。
- 模型不可用时给出明确状态，保留用户选择，不能静默替换模型。

完成标准：自定义模型可被列出、选择并执行；保存和重启后的模型一致；目录返回的思考档都可用，不支持的档位不会先改变持久化配置。

### 4.2 上下文用量

Worker 返回当前模型窗口及当前有效上下文用量，服务层映射到已有 `context_tokens`、`context_window`、`context_percent`，不另建上下文前端协议。

- 使用上游 `calculateContextTokens` / `estimateContextTokens`，基于当前分支和有效上下文计算。
- 累计 session stats 用于总 token/费用，不能当作当前上下文占用。
- 压缩或导航后重新计算，不能继续显示压缩前的 usage。
- 首轮尚无有效 usage 时，token 和百分比返回 `null`；模型窗口已知时可独立返回。不能用 `0` 伪装已测量结果。
- 窗口来自当前解析后的模型能力。`model_context_window` 只有确认为该模型的显式覆盖时才覆盖；Settings 写回的缓存不能无条件覆盖另一模型。
- 显式窗口覆盖必须同时进入 Harness 实际使用的模型对象，保证展示窗口与自动压缩判定窗口一致。

完成标准：有有效 usage 后上下文环显示数字；切模型、压缩、分支导航及重启后数值对应当前上下文。

### 4.3 压缩配置与事件

直接使用 Harness 的压缩引擎。当前上游默认设置为 `enabled=true`、`reserveTokens=16384`、`keepRecentTokens=20000`；产品设置需要实际传入和核对。

建立一处共享的配置解析逻辑，供 Settings、Worker 和 session state 使用：

```text
W = Harness 实际使用的当前模型 contextWindow
p = 产品解析后的压缩阈值百分比
reserveTokens = ceil(W × (1 - p / 100))
keepRecentTokens = 20000
enabled = compaction_enabled !== false
```

上游阈值判定为 `contextTokens > W - reserveTokens`。默认阈值也必须由共享逻辑解析并应用；不能在界面显示一个经过裁剪的百分比，实际仍使用另一个默认 reserve。整数舍入、默认值和小窗口行为集中验证。

- 初始化、切模型和修改压缩设置时，重新解析窗口与 reserve，并通过公开的 compaction 配置接口应用。
- 配置仍走已有串行通道；忙碌时遵守现有拒绝或延迟重载规则。
- state 返回已应用的配置，不能仅照抄 Settings 期望值并宣称生效。
- 转发 `compaction_start/end` 到现有 `compaction.updated`；失败产生现有 `error`，正确区分完成、取消与失败。
- 保留手动 `compact`，不把关闭自动压缩解释成禁止手动压缩。

完成标准：关闭自动压缩后不再因阈值触发；改变阈值会改变实际 reserve；切模型后仍一致；手动压缩、取消与失败都能正确更新界面。

## 5. 阶段三：补齐 turn 生命周期与主动恢复

从 `NodeSessionService` 提取与运行时后端无关的产物、复查和统计处理，由 Orbit 与 agent-core 接入。后端状态探测继续分别实现。

- 用户可见的一次 turn 对应一次 prompt/run；不能把每次模型与工具往返的内部 turn 都当作独立产品 turn。
- 文件工具开始前捕获工作区基线，并绑定稳定的请求/operation 身份。不能依赖异步收到 `agent_start` 后才临时拍快照而漏掉早期文件修改。
- `agent_settled` 发布 `turn.artifacts`、最终 `session.stats`，按现有规则触发自动项目复查；失败和取消按现有产物语义处理。
- 通过既有产物与复查记录去重；恢复或事件重放不能重复触发后续动作。需要跨重启恢复的基线保存到工作区持久化记录。
- token/费用继续来自 session stats；墙钟与界面活动时间继续由产品事件投影处理。

增加 agent-core 的事件活跃度/状态探测，复用现有 Worker 管理和会话归属记录：先查询 lane/session 权威状态，再决定重开；确认旧 Worker 已停止后才打开同一会话。恢复使用 single-flight 和有界重试，保留交付不确定状态以及 abort/交互通知的可达性。

完成标准：一次快速写文件的 turn 能展示产物并只触发一次复查；重放和父进程重启不重复处理；杀掉 Worker 或中断事件流后能恢复同一 durable operation，界面收到明确的故障/恢复状态。

此阶段可以继续使用现有 Orbit 复查 runner；其 agent-core 替代在下一阶段完成，因此不能据此宣布 Orbit 已可删除。

## 6. 阶段四：迁移 todo 与 subagent 产品工具

### 6.1 Todo：优先迁移结构化工具

将现有 todo 逻辑适配为 `AgentHarnessTool`，保留工具名 `todo`、既有 action 参数和结果结构。任务状态、依赖和 id 分配采用会话及分支身份，保存在可恢复的会话状态中。

现有前端从工具结果的 `details.tasks`、`details.nextId` 等字段重建任务列表。迁移必须同时处理执行、持久化及历史投影：

- 每次结果携带与现有界面兼容的完整快照，不能只输出 Markdown 列表。
- v4 历史投影保留 `details`，采用已有大小限制；目前 `AgentSessionRepository.asMessage()` 没有投影该字段。
- Worker 重启、页面刷新、压缩及 fork 后，工具状态和可展示快照按既有分支语义恢复；不能只保存在进程内存或界面组件中。
- 复用既有前端任务进度展示，不另建一套 todo 事件协议。

完成标准：创建、更新、完成、依赖和清理行为与现有工具一致；实时结果及冷态历史均能驱动 Inspector/进度展示；不同会话状态不混用，fork 的修改不反写父会话。

### 6.2 Subagent：迁移委派与受控执行

Core 的 lane/session 是执行原语，并不自动提供完整的子代理产品工具。对话中的 subagent 工具需要适配；现有 `ResearchSubagentRunner`、`ReviewSubagentRunner` 分别增加 agent-core 实现，保留各自的生命周期接口。

- 复用既有 agent 定义、输入输出 schema、结果解析和前端展示契约。
- 子任务使用独立的子会话/Worker，绑定父 operation 与工具调用身份；取消、超时、结果汇总及错误传递由产品执行层管理。
- 子任务身份和结果关联持久化。Worker 内存仅作缓存；重试先核对既有子任务，避免重复创建运行。
- 隐藏研究/复查会话继续不出现在普通对话列表；使用明确的归属/用途元数据，保留 v4 工作区存储和路径校验。
- 技能、模型、环境、MCP 和交互审批沿用现有资源投影；子代理不能自行放宽父任务的策略。
- 普通会话、子代理、研究与复查 Worker 纳入统一的资源容量统计，保留 `PI_SCIENCE_IDLE_RUNTIME_MS` 空闲回收，限制嵌套与资源占用。

遵守 [Research Loop ADR](adr-research-loop-subagents.md)：Node 服务继续是研究状态、预算、评估、恢复和停止决策的权威；候选执行仍由 `JobCoordinator` 管理，子代理只承担结构化生成/分析。本阶段保留串行研究循环，不新增并行候选调度，也不新增另一份研究状态机。

完成标准：对话委派及既有 @agent 选择可用；结果和错误能回到父会话；取消能停止子运行；重启能核对状态；Research Loop 的预算、暂停/取消及确定性停止规则保持一致，项目复查使用现有结果 schema。

## 7. 阶段五：存储迁移与其余能力验收

### 7.1 复杂会话迁移

收集并脱敏至少一份真实 v3 样本，包含用户/assistant 消息、工具调用及结果、一次压缩和分支。验证导入后的历史、继续执行、分页、统计、fork、导出及删除行为；同时验证阶段一涉及的既有 v4 会话。

迁移分为副本准备、完整可读性验证、提交归属、启动 Worker 四步。副本验证失败时清理未提交的文件与配置；归属提交后的 Worker 启动失败进入恢复流程，不能删除归属并重新暴露旧源文件。

在真实样本验证完成前，新会话可按开关走 agent-core，旧 v3 继续 Orbit。迁移使用显式入口或独立策略，不因启用新运行时就自动迁移所有旧会话；列表、历史和 state 查询保持纯读取。

已登记的 v4 会话由 agent-core 继续管理，包括删除标记。关闭全局开关不能把这些会话重新路由到保留的 v3 源文件。

### 7.2 技能、模板与扩展清单

列出现有技能、界面及研究流程实际调用的工具和命令，为每项记录“已适配、待适配、明确退役”及对应验证。

- 补 `get_commands`、技能与模板执行入口；按实际可用能力显示菜单。
- 保留资源策略与刷新机制，继续种子化内置工作区资产。
- Web access 复用现有实现或受管 MCP，保留使用中的工具契约与网络策略。
- MCP、Notebook、问卷继续使用当前产品适配，验证恢复、交互和历史；不替换为另一套配置体系。
- context-mode 继续默认关闭，启用与迁移独立评估。

完成标准：使用中的 Orbit 专有能力都有等价路径或明确退役结论；真实研究会话能够完成任务、保留产物、使用 todo/委派，并在刷新或故障后继续。

## 8. 后续独立项：图片 prompt 与工具边界

现有浏览器发送接口只有文本和 `client_message_id`。图片支持需要端到端补齐：前端附件、REST、持久化交付摘要、Worker admission、历史及模型能力校验。

同一请求 ID 的内容摘要和 Worker 冲突检查必须包含文本与图片的实际内容，不能沿用只比较文本的去重。模型不支持图片时返回明确错误，不静默丢弃附件。只有在产品宣布提供图片发送时，才将它纳入相应功能验收门槛。

工具边界继续分项记录：凭据环境过滤已完成；read/write/edit 的路径与符号链接边界尚待补齐；任意 Bash 命令的宿主访问需要 OS 级约束。路径校验不能替代 OS sandbox。按当前约定，本方案不安排 sandbox 实现，暂缓期间不切换默认值。

## 9. 验证、提交与发布

推荐提交顺序：上游升级 → 模型/上下文/压缩 → turn 生命周期与恢复 → todo → subagent/runner → 迁移与剩余能力。每个提交说明对应产品行为及验收证据。

| 验收项 | 必须覆盖的场景 |
| --- | --- |
| 升级兼容 | 新会话、已有 v4、丢失确认、恢复事件、配置回滚、迁移删除、凭据投影 |
| 模型事实 | 内置/自定义模型、不可用模型、支持/不支持的思考档、保存及重启 |
| 上下文与压缩 | 首轮无 usage、压缩后、切模型、覆盖窗口、阈值映射、关闭自动压缩、手动压缩及失败 |
| Turn | 快速文件写入、产物锚点、最终统计、复查去重、取消、重放及重启 |
| Todo | 完整快照、历史 details、刷新、压缩、分支及会话隔离 |
| Subagent | 委派、稳定身份、结果与错误、取消/超时、资源上限、研究与复查 runner |
