# Candidate execution safety

`sandbox_run` is an opt-in local restricted Python research preview using pinned Anthropic sandbox-runtime (srt) 0.0.79. The server operator must run the real platform acceptance tests before enabling it; the default is code generation. Missing dependencies, invalid policy, unavailable isolation or unsupported platforms fail closed. There is no direct host-Python fallback. Only Linux autonomous execution is currently supported. macOS and Windows execution are blocked in the runtime.

Parent workflow: freeze evaluation.yaml and the trusted evaluator outside candidate directories; bind execution_budget with research_id before costly calls; prepare research/<research-id>/candidates/<candidate-id>/input (only an approved data subset) and work; delegate with explicit candidate_id. The server derives the directory from the owning operation's durable research binding. Candidate IDs are literal identifiers, not paths. The delegated runtime cannot choose another candidate; normalized paths, symlink components, hard links and special files are refused. Experimenter has only read and sandbox_run intersected with the Parent's current active tools. Live role/skill/capability revocation still applies. All Experimenter reads require an explicit candidate_id and are restricted to its input/work, even in code-generation mode.

Each invocation gets a server-generated private srt settings file, never repository configuration. denyRead covers /; allowRead restores only trusted system/runtime paths and this candidate input/work. System aliases are canonicalized on Linux. Only work is configured for host writes; input is read only. Network domains are empty, local binding and Unix sockets are disabled, Linux requires the packaged seccomp filter, and weaker nesting/network isolation, Apple Events and PTYs stay disabled. The environment is rebuilt without LLM/MCP/cloud credentials; Python uses -I -B from an operator-selected preinstalled environment outside the workspace. HOME, TMPDIR and caches for Python are candidate-local. srt's own control files and bridge sockets use a short, private server temporary directory hidden from Python.

The shared budget admits sandbox calls atomically across Parent/children and narrows their deadlines. Timeout and Abort kill the process group; Linux PID namespaces contain descendant processes. A trusted watchdog also kills the group on Worker IPC disconnection. The deterministic Execution ID and durable record prevent rerunning the same invocation. Recovery of an unfinished record marks it lost and requires inspection before a new invocation. Candidate execution is serialized across Workers. Code is capped at 64 KiB, each log stream at 64 KiB, published artifacts at 16 files / 8 MiB total, and directory scans at 4096 entries. Only bounded regular top-level .py/.json/.csv/.tsv/.txt/.log/.png/.pdf/.npy/.npz outputs are published through the existing Artifact Publisher, after process cleanup. Linked or special outputs are refused. Running process success is not scientific experiment success.

Known boundaries: srt is a research preview, not a general hostile-code or multitenant security boundary. System binaries and a dedicated trusted Python installation remain readable. Linux read-denied directories may be empty writable private tmpfs shadows: writing there does not change the hidden host file, and those shadow files are never published. No exact CPU/GPU/memory/disk/cost quotas, dependency installation, GPU, R or interactive Notebook execution are provided. Do not expose secrets in the approved input subset or the trusted Python installation. A user or trusted Parent with general tools can still alter workspace state; this does not sandbox the Parent. Unassigned Experimenter children cannot read workspace files, including in code-generation mode. Supply approved context in task text, or bind a candidate and prepare its input/work directories under the research budget.

Real acceptance must cover NumPy execution, actual Execution/Artifact IDs, repair from logs, independent Parent evaluation, protected file/credential/sibling reads and host writes, traversal/aliases/links, subprocess inheritance, network/localhost/Unix sockets, timeout/Abort/Worker death, shared budgets and recovery. Mock tests cannot establish isolation. Linux was exercised during implementation; The first real macOS 26 arm64 run passed file/network isolation and NumPy/Worker IPC, but failed timeout/Abort and detached descendant cleanup, including kill EPERM. macOS is therefore blocked even when the operator sets the enable flag; it remains code generation only. A future native containment solution must pass the original execution tests before lifting that runtime gate. See docs/auto-research.md for configuration and commands. Research-ID generation/binding redesign remains a separate follow-up.

If a previous run leaves rejected outputs (links, special files, excessive entries, file count or artifact bytes), the next sandbox_run resets only that candidate's canonical work directory under its lock before executing. All previous work files are removed; input and external link targets remain untouched. The result reports this reset in limitations. Invalid input or directory aliases still fail closed. Original source, logs and already published artifacts remain in durable records.
