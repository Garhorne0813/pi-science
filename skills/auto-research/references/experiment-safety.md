# Experiment safety and capability boundary

The current runtime has no candidate filesystem/process sandbox. Experimenter therefore has read only and generates proposed code as text. The parent inspects code before saving or running it through existing controlled scientific tools. Parent-controlled execution is not a sandbox: run only code whose effects the parent can validate; if isolation is necessary, stop and report the missing environment. Do not execute untrusted candidate code merely because it was generated by a child.

Before enabling write/edit or arbitrary execution in a future runtime, enforce candidate-only writable mounts; read-only or invisible evaluator, evaluation.yaml, baseline, original data and sibling candidates; normalized paths and symlink/absolute-path/.. protections; process/file-handle containment; CPU/memory/disk/GPU/time caps; default-denied network; no unnecessary credentials. Write/edit path checks alone cannot contain Python/Bash. Test direct writes, symlinks, traversal and process bypasses before claiming autonomous execution.

The main Agent freezes and validates the evaluator separately. Protocol revisions preserve old versions, explain changed criteria and re-evaluate affected candidates. Reviewer remains independent and read only. Budget reservations count admitted calls (including failed/cancelled calls), not script-internal experiments. Use a persistent execution_budget research_id before retrieval/delegation/computation; children inherit the same remaining allowance, cannot change its scope and can only narrow limits. Checkpoint actual semantic experiment counts and resource usage separately. Never claim OS resource isolation or exact experiment/token/cost metering from call accounting.
