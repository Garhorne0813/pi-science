# Experimental research

Understand → freeze protocol and resource limits → validate task-specific evaluator with known answers and edge cases → measure baseline → review design when useful → delegate separate candidate hypotheses → independently evaluate → review validity → parent retains/rolls back/iterates/stops. Retrieve methods or benchmarks with Researcher as needed, including when an experiment reveals an evidence gap.

Give each Experimenter candidate_id, hypothesis, protocol/evaluator versions, permitted candidate directory, read-only inputs, local share of remaining budget and expected result schema. Use distinct research/<research-id>/candidates/candidate-001 and candidate-002 input/work directories. Bind execution_budget.research_id before costly calls and assign candidate_id explicitly on each subagent task. With operator-enabled, platform-validated srt, Experimenter may use sandbox_run, inspect actual logs and repair within the shared budget. Otherwise it returns proposed code in code-generation mode, with no host execution fallback. See experiment-safety.md.

The parent inspects proposed code and uses existing bounded computation tools. Run one identified candidate per controlled execution; scripts can contain loops, so tool counts do not measure semantic experiments. Evaluate all comparable candidates with the same protected evaluator, split, seeds and baseline. Never accept candidate-reported metrics as final. No evaluator ships with this skill: build or select a task-specific evaluator. Final-test tuning is a blocking validity failure regardless of improved metric.

Persist candidate result fields: experiment_id, status (proposed/running/completed/failed/cancelled), hypothesis, protocol_version, evaluator_version, candidate_path, input/code/data/evaluator digests, parameters, metrics (independent evaluation only), raw_outputs, run_refs, artifact_refs, environment_digest, resource_usage, limitations. Do not fabricate run IDs or hashes. Mark complete only after real results arrive. On resume inspect completed and running records before retrying; reuse matching results, and re-evaluate affected results after protocol revisions rather than mixing versions.
